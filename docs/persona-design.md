# 西界 · 让找到的 TA 成为能认出来的聊天对象

产品设计提案，2026-11-19。首个体验目标是隐去名字、头像和口头禅后，熟悉 TA 的用户仍能从 TA 怎么听、怎么回应、过几天还记得什么，认出自己找的是谁。

## 从「找 TA」到第一次聊天

用户照常找 TA。凡是现有流程已经接受的资料，人物匹配直接复用，新增必填项、逐项确认和必经页面均为零。从草稿继续时也沿用已填内容。用户可以完成原有的找人流程、进入聊天，全程不打开「再调整」。人格问卷、音色测验、资料完整度提醒和借聊天补齐字段的连续追问均排除在流程外。

故事中有明确线索时，原预览可露出一两句日常描述，例如「你说过，阿禾总会把最后一块饼留给人，递过去时只说『多的』。」证据收在现有折叠区。只有少量资料时，让未知经历保持未知，后台采用稳定、克制的表达；音色沿用已有选择或自动匹配可用标准声。画像整理、试听或语音供应商暂时不可用时，文字交流按已有文字服务状态继续。自动选音色本身不会触发播放。

现在的自动提取一次最多保留 6 条明确线索和 1 句口头禅。手工资料已支持最多 30 条自由性格描述，界面的四个预设控制对话语气。私聊已经读取人物资料和适用记忆。世界中也已有明确启用后每日最多产生一件小事的离线生活。此次提议新增的部分是从自由叙事得到可追溯的行为倾向、随事件变化的心情、能跨日接续的配角关系。[人物线索](../backend/services/people/src/profile-clues.ts) · [资料投影](../backend/runtime/model-execution.mjs) · [生活事件的现有执行范围](../backend/services/conversations/src/story-provider.ts)

## 不同素材各自能说明什么

| 输入 | 可以采用的线索 | 对角色的影响 |
| --- | --- | --- |
| 用户写下的故事和聊天原话 | 谁做了什么、对谁、在什么场合、当时说了什么。排除转述他人的行为、否定、玩笑和假设 | 「聚餐时她往往最后开口，聊起花却停不下来」保留这两个适用场合。单次观察可以先存为一段经历。 |
| 用户标明为 TA 本人、且用途已覆盖的录音 | 逐字原话、惯用称呼、在清楚片段里反复出现的语速和停顿。用户口述自己的回忆时，讲述者和故事中的 TA 是两个人 | 内容可为故事补证，语速可指导语音表达。短句、噪声、多人混说的片段可以留空。音色仿制是另一个用途。 |
| 用户上传的照片和配文 | 画面可见一架缝纫机；用户配文写「她每年给我改校服」 | 前者只用于谈这张照片，后者才支持一段关于照顾方式的回忆。照片里出现工具一次不足以确定职业、爱好或所有权。 |
| 用户说明的年龄、称呼、性别、体型、身体情况 | 年份在用户说明的时间线中换算；按指定称呼交流；「走久了膝盖不舒服」可影响获准的活动安排 | 人口与身体资料不参与性格打分、随机权重或配角分配。身体信息只在用户主动给出、愿意用于相关情境时使用。 |

同一个人的不同照片会引出差别很大的性格印象；公开视频性格印象数据也测出了观察者对感知年龄、性别及外貌吸引力的偏差。西界值得从照片里找回的是「那架缝纫机」，从录音里找回的是「她喊我的那一声」。[同一人的不同照片实验](https://journals.sagepub.com/doi/10.1177/0956797614532474) · [视频人格印象标注复核](https://arxiv.org/abs/2011.14906)

## 怎样匹配，怎样随机

1. **拆成独立线索。** 每条记录保留行为、说话者、指向的对象、场合、来源位置、版本。把「她来接我，嘴上说顺路」记录成一次具体的照顾和一句原话。「她从来不这样」保留否定。TA 自己以前生成的台词不能为同一猜测反复加分。
2. **给倾向加适用范围。** 对单次举动保留例子；对用户明说的习惯或反复出现的独立例子，给相关维度一个偏好区间。「对生人安静」可以和「在家很爱讲故事」并存。来源相当又说不清时保持未定。用户明确纠正或手工设置的表达优先。产品只展示日常措辞，内部区间用于选行为。
3. **在相容范围内抽取一次。** 先排除和已知描述冲突的表达组合，再用同一份草稿的稳定随机种子，从相容的候选里抽一组长度、主动程度、回应方式等。素材很少时从温和范围抽少量表达细节，称作「西界演绎」。姓名、面孔、声纹、年龄、体型和健康均不进入采样。现实记忆中空缺的病史、家庭成员、工作和共同往事保持未知。
4. **保存用户看到的那一版。** 候选绑定草稿、资料版本、字典版本和种子。种子只用于在相容候选中抽取，模型重跑仍可能产生不同措辞。People 现在会在读取预览和确认时分别计算线索，引入模型后必须持久化已选候选，确认时原子采用。刷新、重试、换设备只读回同一结果。补充或删除素材仅重算有依赖的维度，用户纠正的项保持有效。
5. **每次回复只取有关的东西。** 先看用户此刻想表达什么，再选一两条最相关的行为或关系记忆，必要时带上一件有效的世界事件。每次关心人都重复同一动作，也会变成模板。沉默片刻、讲自己的看法、坦白「这件事我记不清」，都可以是合适的回应。

每个设定区分「你提供的」「根据故事整理的」「西界演绎」，世界中实际落定的事另记为「西界经历」。用户愿意调整时，可以在原聊天里说一句，也可以打开现有人物设置。「这条慢一点」只调整本条；「她平常说话就慢，以后都慢一点」是明确的长期纠正，在相关用途许可内只更新这位人物的节奏。范围不明确时先照顾当前一轮，继续聊原话题。旧人物沿用原故事、自填标签和语气，用户再次见到 TA 时无需补录。

## 模型怎样塑造同一个人

「平时不怎么哄人，真有事时会陪到最后」是一个有用的人物设定，靠查找“温和”这个词很难得到。建议让模型从自然语言中提出**有适用场合的表达习惯**。字典帮助团队比较和评测；有原话支持、但难以归入现有维度的习惯，可以直接保留。无需穷举所有性格或为每种组合写固定台词。

| 时机 | 模型拿到什么，产出什么 | 服务端和产品负责什么 |
| --- | --- | --- |
| 找到 TA 或补充资料 | 人物画像任务只读取本次用途可用、标明说话者的资料，提出候选。每条包含一句行为描述、适用场合、证据引用，可选关联维度；无法判断时返回空。允许同一个人在不同关系中有不同表现 | 校验证据片段和版本确实存在，区分用户原话、模型归纳和虚构补全。按人物、草稿版本、配置版本去重。只采纳首次校验通过并已保存的候选。模型超时可沿用原故事开始聊天，候选迟到不得覆盖已确认或后来手改的设定 |
| 用户说了一句话 | 用人物平时的表达、对**这个人**的相处习惯、TA 自己当前有效的心情和本轮原话，一次生成回复。允许适用的渠道在同一次生成中附上少量朗读建议。模型自己组织语言，示例台词不充当运行时答案 | 当轮明确要求优先，例如「今天别逗我」。用户说「我很难过」说明用户的处境；TA 可以收起玩笑，自己的心情仍有独立来源。更新长期习惯须有明确纠正或新的有效证据。普通文字回复无需等待语音服务 |
| 用户点击朗读 | 在相应用途覆盖后，用已保存的正文、已选标准声音及允许的少量表达控制合成。朗读模型只需演绎这句话 | 绑定原消息版本、声音版本、本轮表达和合成配置，核对声音回执及朗读文本后再提供播放。同一已生成版本直接复用，播放设置里的 1.25 倍速仅作用于听的人 |
| 用户开启实时通话 | 实时模型直接听、回应及停顿，可在本通电话内适应语境。使用当前通话获准的人物最小资料和同一份声音选择 | 建连时锁定声线，允许用户插话并停止旧音频。只播出一半时，让后续轮次以用户实际听到的部分为准。当前通话不留逐字稿，不将电话里说过的事自动写入聊天记忆 |

**模型与参数如何更换。** 复用现有按用途选择文本模型的入口。为画像整理设立独立执行用途；私聊、世界行动、围坐、书信、朗读和实时继续使用各自的模型配置与资料范围。一份有版本的服务端配置记录每个用途的模型引用、提示词版本、输入字段、返回格式、语言、能力、超时和预算。有些模型支持结构化输出或采样控制，只有通过该适配器验证的参数才会发出。首版可以由同一文本模型承担画像和对话，分别评测；有质量或延迟证据再换其中之一。更新配置先用虚构人物回放对照，可按版本回退。服务端另行执行账号权限、来源、额度、世界行动和可用声音校验。模型产出的文字和编号不能改变这些规则。[文本模型选择](../backend/runtime/model-execution.mjs) · [现有执行用途](../backend/services/identity/src/model-execution.ts)

主线普通聊天和带世界行动的聊天分别走两个适配器；后者已有严格的行动返回格式。接入时给支持的版本加一个内部返回包，先验证原有正文与行动，再单独验证可选的朗读信息。单独缺少或损坏朗读信息时，合法文字仍可展示；行动校验失败仍按原规则处理。围坐、分支和信件复用人物基本表达，各自保留说话者、在场者、时间线和可见资料边界。语气可以一致，知识范围取决于当时 TA 能知道什么。[主线聊天](../backend/services/conversations/src/provider.ts) · [世界行动](../backend/services/conversations/src/world-action-provider.ts) · [围坐](../backend/services/conversations/src/gather-provider.ts)

## 音色、语气和每句话的读法

| 用户能听出的区别 | 谁来定 | 在西界的表现 |
| --- | --- | --- |
| 音色与声线身份 | 有用户已选声音时沿用，其余人物由后台在目标语言实测过的可用标准声线中稳定选一次，保存声线、具体音源和版本 | 第一次聊天可以直接使用。用户日后想调声音时，才从已有入口试听和更换。新选择用于下一次生成，过往已生成且仍可播放的语音保留原声 |
| 对人说话的语气 | 模型结合长期性格、两人关系和这一轮的意图 | 同一句「我考完了」，熟悉的玩笑、郑重的祝贺、只听用户说，都可能合适。用户补充「成绩很糟，别说恭喜」，这一轮就收住。口头禅可以很久都不用 |
| 语音表现 | 模型建议少量相对 TA 平日的变化，适配器使用已实听验证的控制 | 改语速、停顿、重音或能量，仍用原声线。文字里的长短句也影响节奏。把聊天写得更简短、把原文读得更慢、把手机播放速度调低，是三个独立操作 |
| 用哪种语言，怎样念称呼 | 优先用户明确要求的交流语言，再看当前对话。界面语言只作资料不足时的默认值。用户提供的名字读音可保存为显式偏好 | 用户说「老板就回了个 fine，你陪我会儿」时仍可以用中文接话。昵称和引用保留原样，对家乡话或多音字只承诺当前音源验证过的读法 |

**让试听兑现。** 今天的搜索页用浏览器自带声音，并以固定语速和音高模拟音色；私聊朗读固定使用 `marin`；实时适配器把三档偏好映射到三个标准声，同时要求所有角色简短温和。新版应由同一份经过试听的**声线目录**供三个入口查询，目录按供应商、具体模型、语言和渠道记录实际支持的声线与控制。试听用无私人内容的样句和同一实际音源，界面保留试听和原来的调节入口。例如听同一句「你来了，我给你留着座」，用户能判断哪个声音更合适。旧版三档作为迁移线索，已明确选择的对应音源优先保留；旧资料空值保留“自动”。[搜索页试听](../frontend/src/seek.tsx) · [私聊朗读](../backend/services/conversations/src/reply-speech-provider.ts) · [实时声音](../backend/services/conversations/src/voice-provider.ts)

**能力不足时的听感。** 声线支持、表演控制支持、目标语言实听效果分别登记。声线可用但不支持精确停顿时，用同声线自然朗读。声线或该语言不可用时保留正文，在播放入口就地显示可选的替代声音，用户选择后才切换。有供应商声音下架时用同一处理方式。OpenAI Realtime 在本次会话首次发声后就锁定声线。因此通话中申请换声从下次通话生效。通话打断要同时停止设备待播声音，按实际播放位置截断模型的会话记录，避免下轮接着一句用户根本没听到的话。[Realtime 会话与打断](https://developers.openai.com/api/docs/guides/realtime-conversations)

**传给语音端的内容。** 当前私聊朗读授权仅允许发送用户主动点选的已保存正文，明确排除了人物资料、记忆和原声。现有授权继续走标准朗读。新版若要发送人物声音偏好或由对话推导的表达参数，应在现有相关入口清楚说明增量并记录覆盖范围；已覆盖时直接使用。正式通话当前仅使用已授权的最小画像与麦克风。用户上传的录音属于素材，声线选择从标准音源开始。历史录音的转写、分析或定制声线各自核对用途，不能随供应商配置切换而静默启用。[私聊朗读说明原文](../backend/services/identity/db/035_chat_reply_speech.sql) · [实时通话说明原文](../backend/services/identity/db/027_person_voice_calls.sql)

**一条可供实现的内部接口。** [单条朗读意图的 JSON Schema](./persona-delivery.schema.json)只传相对演绎变化。比如同一条已经保存的「嗯，你慢慢说」，下面的提议表示稍慢、句间多留一点空间。数字是相对这位 TA 平时的幅度，实际秒数、播放速度或供应商参数由音频适配器校准。同一句也可以用空的 `adjustments` 自然念完。

```json
{ "version": 1, "adjustments": { "pace": -0.2, "pause": 0.25 } }
```

结构校验限制数量、数值和可传字段；服务端还要在**本轮允许的表现项目录**中查每个键。接入时用已核准的键列表收紧 `adjustments.propertyNames`，无可用控制时仅接受空对象。目录可以扩充。任何未知键或非法数值都会使本条演绎建议失效，改用已选声线的自然读法。声线 ID、模型路由、业务操作和整段自由提示词都由服务端控制。旧消息缺少这份数据时也能按原范围朗读。

## 情绪、关系和 TA 的生活圈

| 变化速度 | 存什么 | 例子 |
| --- | --- | --- |
| 长期稳定 | 行为倾向，表达偏好，用户特别指出的习惯 | 爱拿自己开玩笑；对陌生人慢热；着急时反而话少 |
| 随关系积累 | 如何称呼用户，哪些玩笑合适，最近在意的事，上回约好再聊什么 | 用户说周五有面试，周五以后再聊时可以自然问起；用户说不想聊，先收住 |
| 数小时到数天 | 心情、精力、触发事件、生效时间、回落规则 | 今天修了半天也没修好一件东西，说起它时有点泄气。用户正难过时，TA 可以放下自己的事先听 |
| 随世界推进 | 少量固定虚构熟人、各自的兴趣、和 TA 的关系、最近见面的已提交事件、一件未完成的小事 | 同一个修车摊主隔几天再出现，知道上次借了什么。一次只推进一小步，也允许几天没进展 |

首版生活圈建议每个世界从一两位虚构熟人和一件小事开始。熟人有固定身份，有自己的事情可做；偶尔意见不合也能自然相处。计划和已经发生的事分别保存。世界事件提交后，TA 才能把它当作经历讲出来；当前只支持单人的离线任务，配角共同活动需扩展参与者和时间线契约。暂停离线生活后没有后台补写；主线和各分支只读各自有权知道的进度。用户离开多久不触发埋怨、催回或扣减关系值。这个方向可借鉴 Generative Agents 对记忆检索和计划的实验，现有西界服务足以先做一个小圈子的验证。[Generative Agents 原论文](https://arxiv.org/abs/2304.03442)

**三次相遇的设计样例。** 虚构人物阿禾习惯动手帮忙，不爱说漂亮话。用户今天说「面试砸了，先别劝我」，阿禾回「行。那我坐会儿，你骂，我听着。」过两天用户说「那家公司又来电话了」，她回「上回那家？这回你想听听，还是看见号码就烦？」同一个人也有自己的事。假设世界里已记下她向邻居借线修伞，用户问「你那把伞呢」，她可以说「线借来了，还没缝。我一看那排细针脚就想先喝口茶。」再问才展开，不把用户每一次难过都拐到伞上。

## 接入顺序和验收

| 顺序 | 工程落点 | 验收方式 |
| --- | --- | --- |
| ① 找 TA → 稳定画像 → 文字私聊 | People 保存版本化候选及证据，随原有确认动作采用。把人物表达接入实际的两条主线文字路径，同轮产出允许的朗读建议 | 用现有服务可接受的最少资料走完，从打开「找 TA」到第一条回复，新增必填项与确认次数都为零。中途恢复草稿能接着走。刷新和重试后画像一致，用户当轮纠正与长期纠正范围正确。相同故事和种子只改外貌或年龄，性格输出应一致。 |
| ② 打通试听与主动朗读，再验证实时通话 | 人物共用声线目录与版本，适配器分开。语音项目可用前可验证目录、消息绑定、回执异常和权限边界；到真实供应商与设备上验证听感 | 分别用自动声线和手选声线走通试听、已获准的主动朗读；实际音源与对应选择一致。全程略过试听仍能完成文字对话。读错正文或返回其他声音时不得发布。中英混说、人名、改声后的新旧消息、插话后能否立即停声逐项实听。 |
| ③ 关系记忆、心情，再扩展生活圈 | 先以已有来源和世界边界更新状态。再在离线计划上增加固定虚构熟人、共同事件和未完成事项 | 跨三天验证约定接续、心情回落、用户纠偏和删除源后停止引用。同一件借物不能同时已归还和未归还；兄弟分支不串线，暂停离线生活后不补写。 |
| ④ 照片与录音补充画像 | 优先用户配文与明确归属的转写。原素材存储、单条聊天看图、朗读播放和人物画像分别核对用途 | 只有照片时不产出真实人格结论；上传者自己在讲故事时不把 TA 的声线学成上传者的；删除或撤回素材后派生线索一并失效。 |

**把“像 TA”和“这次说得合适”分开检验。** 先选两位都话少、关心人方式不同的虚构人物，固定模型和题目，打乱新旧版本顺序，遮住姓名、头像、口头禅和音色，请熟悉设定的测试者盲配角色并指出认出的那一句。再固定同一台词、同一声线和播放音量，换成重逢、报喜、用户不想说话等场景，盲听哪次读法最合适。最后拿试听、朗读和实时通话里三段不同的句子混排，看听众能否认出同一声线。分别记录辨认结果、情境合适度、换声、事实冲突和纠偏失效。接口校验与模型打分无法替代真人实际听测。版本化画像、声音选择、状态与关系随相应人物导出、删除和擦除。
