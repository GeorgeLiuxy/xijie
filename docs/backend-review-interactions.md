# 西界后端设计评审 · 用户交互与状态

以下图示为**目标行为**。代码现状、需评审的决定、后续通过条件各自列出。图中接口编号沿用既有规范，批次 K01–K05 为核心闭环，R01–R02 为复访与赠礼，M01–M03 为收费、邀请与公开共创。 [接口总规范](./backend-api-contract.md) · [交互清单](./backend-interaction-inventory.md) · [交付优先级](./backend-delivery-priorities.md)

## 01 · 先体验，再保存到账号

**K01 拟议交互。** 相见入口允许「先看看」，体验用示例资料。用户要上传真实照片、保存私人资料或跨设备同步时，使用一个「继续」入口。首期选一个已验证的登录方式，例如手机号验证码。首次验证成功建立正式账号，返回用户验证前的操作。已验证的旧用户继续使用原账号。

~~~mermaid
flowchart TD
    start(["首次打开或会话过期"]) --> choose{"现在要做什么"}
    choose -->|"先看看"| sample["体验示例人物与星图"]
    choose -->|"登录或保存私人资料"| login["继续并建立登录尝试"]
    sample -->|"尝试上传、保存或同步"| login
    login --> verify{"身份验证结果"}
    verify -->|"失败或取消"| returnLocal["回到原入口，保留可编辑内容"]
    verify -->|"成功"| account["解析已有账号或首次建号"]
    account --> allowed{"原操作仍可用且属于当前账号"}
    allowed -->|"可以"| resume["回到原操作，由本人确认提交"]
    allowed -->|"不可用或无续办"| home["打开可访问的默认入口"]
~~~

| 要核对的行为 | 实施后通过条件 |
| --- | --- |
| 只浏览示例、退出验证、验证码失败 | 无正式账号及奖励写入，回到原入口，可继续编辑明确保留的本机草稿 |
| 同一可信身份并发完成首次验证 | 一个 `accountId`、一条正式注册事件；后续登录仍使用这个账号 |
| 登录前选过资料，验证成功时原目标已移除或属于另一账号 | 安全回退，不显示原对象，不代用户提交上传、发礼或购买 |

目前 `App.tsx` 在未登录时直接显示 `AuthFlow`，本机登录成功固定回到相见。游客入口和按动作恢复尚待实现。现有契约的 `returnRouteKey` 是白名单入口，原操作参数与本机草稿可由当前尝试临时携带。恢复前重新校验登录账号、资源和权限，用户主动确认后再写入。Web 走 IAM-01/02，原生走 IAM-01/03。原生回跳和现场安全存储待真机验证。 [当前登录入口](../frontend/src/App.tsx#L531) · [身份接口](./backend-api/identity-people.md#1-身份引导和会话)

## 02 · 切账号与退出

**K01。** 从「我 → 账号与安全」发起切换。切换期间 A 保持当前会话。B 的凭据、当前尝试及代次均验证通过后，服务端在同一事务内替换会话。切换成功后客户端隔离会话流、搜索、草稿和媒体缓存，再读取 B。原账号的订单与已受理任务继续按原账号和当前权限处理。

~~~mermaid
flowchart TD
    active(["A 正在使用"]) --> attempt["发起切换，暂存候选身份"]
    attempt --> result{"哪一步先被服务端受理"}
    result -->|"取消或过期"| keep["保持 A，丢弃候选凭据"]
    result -->|"候选验证通过"| commit["检查尝试与代次，撤 A 启 B"]
    commit --> reload["清理 A 的活动缓存，加载 B"]
    keep -.-> late["迟到回调复核，不能替换会话"]
    reload -.-> lateResponse["丢弃来自 A 的迟到界面响应"]
~~~

- **通过条件**　A → B → A 后各自资料一致。取消先提交时，迟到的 B 回调不能切换。验证先提交而响应丢失时，重查当前会话后恢复实际结果。退出只撤当前设备的应用会话。
- **实现接口**　IAM-04 取消尝试，IAM-05 回读会话，IAM-06 退出。找回或增加登录方式沿用原账号，绑定需要有效证明，保留可用的登录方式。
- **当前证据**　前端切换弹层和本机分区在代码中存在。正式会话撤销、原生令牌切换、跨设备隔离待联调。 [前端切换与退出](../frontend/src/App.tsx#L522) · [应用会话接口](./backend-api/identity-people.md#1-身份引导和会话)

## 03 · 寻找 TA 与素材

**K02。** 「称呼、关系、故事」构成最短入口，照片可选。用户可以查看候选、修改草稿或选择只按输入预览。候选显示来源和 AI 呈现说明。确认时选择可用世界，一份草稿只确认成一位人物。

~~~mermaid
flowchart TD
    draft(["建立或继续草稿"]) --> edit["填写称呼、关系与故事"]
    edit --> photo{"是否添加照片"}
    photo -->|"跳过"| preview["请求当前版本的预览"]
    photo -->|"添加"| upload["短时上传槽，校验固定对象版本"]
    upload -->|"通过"| preview
    upload -->|"失败"| edit
    preview --> decision{"是否确认当前候选"}
    decision -->|"修改或重新生成"| edit
    decision -->|"选世界并确认"| person["保存同一个人物 ID"]
~~~

- **通过条件**　上传失败仍可继续纯文字。修改草稿后旧候选不能确认。两次提交只产生一个人物。旧上传链接再次写入不能替换已经校验的对象版本。
- **实现接口**　PER-01/03 管理草稿，MED-01/02/03 上传并查询校验，PER-05/06 请求预览与回读，PER-07 以版本条件确认。人物成立后按需打开会话。 [人物与素材接口](./backend-api/identity-people.md#3-私有素材与用途)

## 04 · 发送消息、AI 回复、珍藏与星图重读

**K03–K04。** 发送成功表示消息已保存且生成任务已受理。AI 回复可稍后到达。回忆候选可编辑，只有用户确认后才生成正式原文。星图、人物资料和聊天入口打开同一个 `personId + memoryId`。

~~~mermaid
sequenceDiagram
    participant App
    participant API
    participant DB
    participant Worker

    App->>API: CHAT-02 打开或复用直聊
    App->>API: CHAT-06 发送，携带 clientMessageId
    API->>DB: 同一事务保存消息、序号与生成任务
    API-->>App: 202 已受理，返回原消息与 jobId
    Worker->>DB: 领取任务并核对授权及来源版本
    Worker->>DB: 模型返回后复核当前尝试并保存回复
    App->>API: CHAT-04 回读，断线可先查 GEN-01
    App->>API: MEM-01 请求候选，或自己写回忆
    App->>API: MEM-03 确认编辑后的原文
    API->>DB: 原子保存回忆、来源和确认事件
    App->>API: FIND-01 在另一设备搜索
    API-->>App: 返回真实人物与回忆 ID
    App->>API: MEM-05 读取同一份授权原文
~~~

| 失败或变化 | 实施后通过条件 |
| --- | --- |
| 发送成功但应答丢失，App 重开后重试 | 原 `clientMessageId` 回同一消息和任务。未受理前保留输入 |
| Worker 中断，用户主动停止或撤回许可 | 失败可重试时复用业务任务 ID。取消或撤回后迟到任务不能提交。已保存消息可正常回读 |
| 候选过期、被修改或已消费 | 保留用户已编辑的文字，可重读或明确改为手写。一个候选最多产生一份原文 |
| 删除原文或出现过时搜索命中 | 旧深链返回 404，旧索引不显示已删除或编辑前的片段 |
| 设备 1 保存，设备 2 登录同一账号 | 可从搜索打开相同 ID 和原文。AI 回响失败不影响已保存原文 |

现在文字回复由本机规则生成，回忆及聊天随本机资料存储。正式生成、队列恢复、跨设备读取待联调。SSE 只提示资源变化，断线用 SYS-02 补读或查询权威详情。 [本机回复](../frontend/src/person.tsx#L240) · [会话与回忆接口](./backend-api/conversations-memories.md) · [公共事件](./backend-api-contract.md#3-共用数据接口)

## 05 · 送礼、收礼和邀请

**R02。** 礼物从聊天输入区或人物场景发起。寄出后，聊天、回执和空间引用同一个投递 ID。收到的礼物以消息呈现，点开详情后可按规则收下或陈列。资产记录从同一账本读回。

~~~mermaid
flowchart LR
    composer(["聊天或人物空间"]) --> pick["选礼物、数量和来源"]
    pick --> send["确认寄出，扣减与回执同事务"]
    send --> delivery["处理中，随后抵达或明确失败"]
    delivery --> card["会话卡片更新原投递状态"]
    delivery -.->|"抵达且有剧情回礼"| received["生成独立收件消息"]
    received --> open["点开详情，再决定是否陈列"]
~~~

**M02。** 从「邀请朋友」创建分享。受邀方打开链接时只创建短时邀请意图。首次验证建号才能绑定归因，首条合格回忆确认后，由服务端给双方分别发券一次，进度和到账从系统消息及资产回读。

~~~mermaid
flowchart LR
    share(["打开有效邀请"]) --> intent["记录短时邀请意图"]
    intent --> verify{"首次真实建号且符合资格"}
    verify -->|"已有账号、自邀或失效"| normal["继续使用，奖励不成立"]
    verify -->|"成立"| pending["已归因，等待首条合格回忆"]
    pending --> confirm["用户确认合格原文"]
    confirm --> ledger["双方各入账一次"]
    ledger --> notice["系统消息与资产可查询"]
~~~

- **通过条件**　两台设备争最后一张券仅一次扣减，丢应答后用原操作键查回。重复打开礼物、重复陈列或重放任务不增加资产。受邀人登录前打开链接不算注册，示例、导入或重复确认不发奖。事件乱序能复核并收敛。
- **需评审**　奖励活动的有效期、首条合格原文的口径、发奖后删除原文时的权益处理。发奖事实可按原账本追溯。
- **当前证据**　礼物、邀请主要读写本机账本或 Vite 预览记录。正式多人并发、跨设备到账和真实新注册归因待联调。 [礼物投递与收件接口](./backend-api/assets-commerce.md#礼物和资产-http) · [邀请资格与接口](./backend-api/assets-commerce.md#邀请与共创-http) · [预览邀请来源](../frontend/preview-server/invites.ts)

## 06 · 支付、查单与售后

**M01。** 首次发布按一个地区、一个渠道、一个商品做通。用户从资产或余额不足的赠礼流程进入。回到 App 先查原订单。渠道确认付款后，前台可显示「已付款，正在到账」。到账后返回原礼物草稿，由用户再确认寄出。

~~~mermaid
sequenceDiagram
    participant App
    participant API
    participant Channel
    participant Worker
    participant Ledger

    App->>API: 获取报价，创建订单与支付尝试
    API-->>App: 受理支付尝试，返回原订单 ID
    App->>API: 读取同一尝试直到取得拉起参数
    App->>Channel: 按渠道 SDK 或页面付款
    App->>API: 回跳或重开后查同一订单
    Channel->>API: 通知交易证据，渠道方式验签
    Worker->>Channel: 必要时主动查单，核对归属及交易
    Worker->>Ledger: 锁原订单，唯一发放并记录流水
    App->>API: 查原订单与到账结果
~~~

| 失败或变化 | 实施后通过条件 |
| --- | --- |
| 关收银台、付款后关 App 或通知晚到 | 结果未知时继续查询原订单。渠道确认未扣款才关单。迟到真实付款可进入对账 |
| 重复回调、同订单两笔实际成功、处理期间切账号 | 同一订单最多发一次权益，额外扣款单独对账，原订单权益归原账号 |
| 发放失败或退款、已消费权益遇退款 | 保留付款与售后事实。可继续补单或由运营按已定规则处理，权威退款事实到达后才冲正 |
| 购买入口来自赠礼 | 返回保留原收件人、礼物、数量和留言，重新核对余额后由用户确认寄出 |

**需评审**　发行与渠道、退款时已消费权益的规则、原生商品是否可恢复。当前购买状态来自原型模拟。沙箱支付、回调、主动查单、退款及目标端回跳待 V02 和 M01 验收。 [支付与售后接口](./backend-api/assets-commerce.md#商品付款和售后-http) · [购买演示适配层](../frontend/src/commerce/preview.ts)

## 07 · 撤权、注销与旧资料导入

**K05。** 素材用途撤回、人物移除、原文删除和账号注销分别生效。撤权时先收回访问，再清理可重建数据。注销前要求近期验证，客户端在提交前生成并安全暂存只能查这笔注销进度的短期凭据。

~~~mermaid
flowchart TD
    action(["用户请求撤权、移除或注销"]) --> scope{"处理范围"}
    scope -->|"素材、人物或回忆"| revoke["提高相关版本，立即停止新访问"]
    scope -->|"注销账号"| deleteAccount["验证并暂存查询凭据，受理后撤销全部会话"]
    revoke --> fence["阻断旧任务、旧索引和未获授权链接"]
    deleteAccount --> fence
    fence --> cleanup["按规则清理原件与派生数据"]
    deleteAccount --> receipt["原注销凭据仅查询本单进度"]
~~~

- **通过条件**　撤权后查询、旧素材引用、投影和在途任务不能恢复访问。需即时撤回的素材使用授权流，普通短签名链接仍受其有效期约束。删除一条消息只隐藏其来源关联，已由用户确认的独立回忆按其自身授权处理。
- **通过条件**　注销应答丢失时仍可查同一受理单。恢复备份后先核对撤权和删除状态，再开放流量。授权后导入同一来源两次应复用原映射，演示余额与旧邀请奖励不进入生产账本。
- **实现接口**　PRV-03 用途授权，MED-05 素材移除，PER-13 人物移除，MEM-07 原文移除。PRV-04 受理注销或导出，PRV-10 受控查回注销进度，PRV-07–09 处理导入。正式后台与恢复流程待实施。 [数据权利接口](./backend-api/identity-people.md#2-同意数据权利和导入)

| 批次与入口 | 交互与状态 | 实施后通过条件 |
| --- | --- | --- |
| R01 星图迁居、小聚、书信 | 迁居后使用同一人物与直聊。世界小聚按当前成员资格开放发送。书信保存解析后的送达时间 | 迁居后原私聊和回忆均可找回。老小聚成员不足时历史可读。App 关闭后回信仍按计划仅到达一次 |

## 评审时建议先确认的四个决定

1. **首期入口。** 先体验示例，再在上传、保存或跨端同步时触发认证。明确首发地区、端、一个真实认证方式，以及登录取消后保留的本机内容。
2. **私人资料与模型。** 明确照片展示许可与 AI 使用许可各自的用途，模型失败时文字预览仍可继续。真实资料开放前完成撤权、注销及备份恢复验收。
3. **奖励与付费。** 确认邀请资格、退款时已消费权益和首发商品渠道。范围可以在对应批次定，账号、回忆、订单与账本的归属关系提前固定。
4. **冻结交付切片。** 先用合成资料跑通 K01–K04，再验 K05 后开放真实资料。每次变化按原批次验收条件检查受影响的接口、数据库约束和用户路径。

本页完成了设计与当前源码的对应检查。图中的通过条件是后续实测口径。正式数据库、外部身份、模型、支付及跨设备端到端结果需各自留证。
