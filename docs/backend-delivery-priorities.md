# 西界功能优先级与交付顺序

依据当前前端交互和后端总体架构。默认先在一个地区、一个主客户端做有限验证，主链从文字会话和私人回忆开始。发布渠道、付费商品、目标年龄范围和真实语音的上线批次待定。下表是交付建议，功能编号沿用现有交互清单。 [前端交互清单](./backend-interaction-inventory.md) · [总体架构](./backend-architecture.md) · [后端接口与实现规范](./backend-api-contract.md)

## 优先级怎么排

| 优先级 | 用户得到什么 | 先后依据 |
| --- | --- | --- |
| P0 核心闭环 | 登录、找到一位 TA、文字交流、确认珍藏、换设备找回原文 | 验证西界的主要价值。账号、授权、任务和原文的规则会被全部后续能力复用 |
| P1 复访与赠礼 | 下次回来接着聊、浏览世界与私人动态、收信、送礼和查回执 | 使用已稳定的人物、会话与事件。先用试用资产验证赠礼价值及钱包一致性 |
| P2 增长与交易 | 邀请好友获得奖励、公开共创、通过一个正式渠道购买并查询售后 | 需要可信的注册和首条回忆事件、权威账本、公开授权及支付渠道资质 |
| P3 条件扩展 | 实时音视频、更多登录或支付渠道、其他世界玩法、运营推荐等 | 按实际用户需求、试点数据和运维成本决定。发布范围单独验收 |
| 并行前置验证 | 认证、媒体、模型、真机发行及支付可行性 | 外部依赖早验证，业务实现按依赖合入。涉及真实用户、公开或收费的门槛单独控制 |

P0 是技术和产品的第一条验收路径。计划对外开放哪项能力，就同步完成它的权限、失败恢复、用户权利和发布验证。若首发必须收费，把 M01 提到该次发布的门槛，仍先验 R02 的正式账本。若试点暂不接旧用户，可延后导入执行，保留旧资料与正式 ID 映射方案。其余现有页面可以保留交互原型。正式环境用同一能力配置限制 UI、API、旧版本和深链接，控制地区、客户端及启用范围。

## 交付批次与可验收结果

| 批次 | 交付范围 | 前置依赖 | 完成条件 |
| --- | --- | --- | --- |
| V01 并行验证 | 确定首发地区、端和登录方式。用候选开源身份服务验证发码、会话、切号及回跳。用合成素材验证上传、访问撤回和一个真实模型的文字请求 | 确定试验环境与服务账号。可与 P0 设计并行 | 目标客户端走通成功、拒绝、取消及回到原页。选择支持的数据处理区域和发布路径。明确证据来自浏览器、沙箱还是真机 |
| V02 并行验证 | 与 V01 并行验证一条候选支付通道。先做资质、商品分类、原生桥、沙箱下单、回调、主动查单和退款可行性 | 首发渠道候选和测试商品 | 真机或对应沙箱可找回同一笔订单。结果影响渠道和接口设计，支付功能按 M01 交付 |
| K01 · P0 账号与共用规则 | 一个正式登录方式、稳定账号 ID、会话恢复、显式退出、取消切号、已验证切号。确定私域隔离、对象 ID、同意与用途授权、接口错误、幂等和事件规则 | V01 中账号链路验证可用。数据归属规则先对齐 | A、B 两账号互换、会话过期、退出与重开后行为正确。直接换 ID、搜索、媒体请求和旧事件流均按归属检查。迟到回调无法切错账号 |
| K02 · P0 寻找 TA 与素材 | 称呼、关系和故事即可确认一位人物。照片是可选的最小媒体切片。支持草稿、预览、确定、资料改动、移除及素材撤回 | K01，V01 中私有存储与权限验证 | 选图失败可重试或继续纯文字。关闭重开找回已接受的草稿或有明确提示。重复确认只创建一个人物。移除或撤回后旧查询和任务按权限失效 |
| K03 · P0 文字会话与任务 | 人物直聊、会话列表摘要、历史、发送状态、AI 回复、取消或失败重试，保留当前账号的输入草稿 | K01、K02。消息与任务同事务提交，模型和权限策略已验证 | 断网、重复发送、Worker 中断、App 关闭或切号后可核对每条消息和生成结果。相同操作只保存一次。模型不能使用未授权资料，未知内容按约定留白 |
| K04 · P0 珍藏与重读 | 用户编辑并确认回忆。用星图或人物资料按人物／记忆搜索，打开同一份原文。支持移除、纠正与回访 | K02、K03。原文与 AI 候选身份分离 | 在设备 1 珍藏，设备 2 登录同一账号可搜索并打开原文。返回聊天时可定位对应人物。删掉记录后旧搜索结果和深链接安全失效 |
| K05 · P0 真实数据试点门槛 | 私人数据读取、复制／导出、删除与账号注销流程。最小支持排障、脱敏日志、任务重试、备份与恢复演练。已有本机资料由本人确认导入 | K01–K04 数据归属已确定。若目标发行涉及其他要求，见上线门槛 | 备份恢复能核对原文和授权，恢复时重放删除与撤权记录。注销阻止新会话及新任务，处理期间可查询状态。导入可重试，未知归属留待确认，演示订单、余额和奖励不转成正式权益 |
| R01 · P1 复访与私人空间 | 世界成员与场景、人物迁居、小聚、完整历史检索、私人空间读写与互动。书信从到期任务生成来信 | K02–K04。共用人物、会话、记忆和媒体权限 | 迁居后人物与私聊 ID 稳定，旧群消息和投递保留历史语义。退出 App 后书信按时到达一次。动态的 AI 回响与原文分开，发布失败保留输入 |
| R02 · P1 赠礼与资产 | 目录、试用邮资、基础券、库存、赠礼、投递／回礼、会话礼物卡、陈列和站内通知 | K01、K02、K03 的人物和会话，先定义账本与事件 | 两端同用最后一张券时只扣一次。扣减与回执一致，超时按原操作查回。一次投递与回礼可在聊天、空间和资产记录交叉核对 |
| M01 · P2 单渠道购买 | 一种商品、报价、支付、待确认、待发放、到账、原订单查询、退款与对账。可恢复权益依商品类型处理 | V02、R02 的正式账本、K01 真实身份。可与 M02 并行 | 回调重复／乱序、付款后进程被关闭、切号、已付款未到账及退款均可恢复。同一订单最多向原账号发放一份权益，重复实际扣款单独对账处理。试用、奖励和付费流水可区分 |
| M02 · P2 邀请奖励 | 邀请创建、公开入口、有效注册归因、首条合格回忆、双方发券、进度和消息 | K01、K04、R02。先确定哪些回忆和注册有资格 | 旧用户、自邀、无效或过期链接、历史导入和重复上报按规则处理。服务端确认资格后两边各到账一次。故障恢复不会多发或漏发 |
| M03 · P2 公开共创 | 共创目标、访客参与、可分享投影、席位、回礼及采纳回忆。先选一个共创类型跑通 | K04、R02。复用 M02 确定的公开链接与资格契约。公开内容的审核和申诉就绪 | 并发争最后一席只成功一次。过期、撤回或滥用时可拒绝。采纳后同一原文可回读，重复采纳或奖励申领不会产生额外权益 |
| X01 · P3 按需扩展 | 语音转写、仿声、实时语音及视频、跨账号真人 IM、更多支付／登录渠道、远程推送、运营化世界与推荐、旧接力 | 根据所选功能依赖 K03、R01、M01 或 M03，以及模型许可、渠道、权限和真机验证 | 每个扩展单独通过平台、权限、成本与中断恢复验收。接力是否保留由公开链接使用情况和产品价值决定 |

推荐第一张开发工单横跨 **K01 → K02 → K03 → K04**，只做一个已登录账号、一位人物、一轮文字对话、一条用户确认的回忆与两设备回读。这样先跑通真实状态与数据流，再按批次补齐功能。K05 在接入真实用户和真实素材前验收，纯合成数据联调可先行。

    invite -.-> share["M03 公开共创"]
    gift --> share
    memory --> share
    paymentTest["V02 支付通道验证"] -.-> pay
    authTest["V01 登录、素材和模型验证"] -.-> auth

## 数据关联与权威来源

| 关联 | 最早要定 | 要守住的规则 |
| --- | --- | --- |
| 认证身份 → 西界账号 → 私人空间 → 人物 | K01、K02 | 西界账号 ID 稳定，多登录方式映射至经过验证的账号。昵称、手机号和本机 `owner` 仅作资料或迁移线索。人物、媒体与历史查询共同校验归属 |
| 人物 → 私聊／同世界小聚 → 消息 → 生成任务与回复 | K02、K03 | 同一人物迁居后私聊身份不变。保存用户原始消息和 AI 回复的关系及实际署名。旧世界的历史呈现语义单列 |
| 人物与素材 → 回忆候选 → 用户确认原文 → 回响／检索 | K02–K04 | 原文归档前要求用户确认。旧条目的来源可空。回响、搜索和动态是可更新的呈现，读原文前重新校验授权 |
| 权益来源 → 账本分录 → 余额、库存或券 → 寄件回执 | R02 | 充值、赠券、扣减、退款来源可追溯。消息卡和陈列引用同一寄件，历史商品保留必要快照。并发用券与扣减受事务保护 |
| 订单 → 支付尝试 → 渠道交易 → 发放任务 → 权益分录 | M01 | 渠道交易按平台、环境和交易号去重，并绑定原始订单所属账号。支付成功与权益发放分别留痕。未知结果查原订单，关闭收银台以渠道返回的最终结果为准。退款以逆向记录核对，处理已消费余额的规则在收费前确定 |
| 邀请链接 → 归因 → 真实注册与首条合格回忆 → 两笔奖励 | K01、K04 先保留来源，M02 落地资格 | 新注册和有效回忆都有可核对的服务端证据。邀请凭据在成功认证后绑定给实际注册的账号。导入、样例和重试默认不计入。已发奖后删除回忆的处理与活动规则一起定稿。并发和乱序事件只产生一份有效归因与两笔对应奖励 |
| 公开凭据 → 有限内容投影 → 访客贡献 → 原文采纳 | M02、M03 | 私人内容默认私有。公开字段须主动选择，失效后只保留按规则可查的记录。贡献按目标与参与身份限额，采纳按来源去重 |

## 用户状态与恢复

按不同维度分别建状态，支持组合。例如「已登录、已有人物、照片待验证、生成中」和「已登录、无人物、邀请待完成」可以同时存在于同一业务模型。

| 维度或对象 | 建议状态 | 会影响的交互与恢复 |
| --- | --- | --- |
| 登录会话 | 未登录、验证中、已登录、需重新验证、切换中、已退出 | 切号取消时保留当前账号。成功后隔离缓存、草稿、搜索、未读和媒体请求。迟到的旧会话响应丢弃。会话过期可验证后回到原操作 |
| 账号存续 | 可用、受限、注销处理中、已注销 | 注销优先停用访问和生成，再按策略清理及回报。可保留的交易记录、待退款和必要售后查询与已删除内容分开。迟到的渠道回调仍归原订单，按注销时的留存与售后规则处理 |
| 使用资格与授权 | 未确认、允许、按地区或年龄受限、已撤回 | 授权范围决定允许的素材、功能与展示。上传、生成开始、结果写回以及签发访问链接时复核授权版本。撤权后拒绝后续处理，已签发短链接按有效期处理。需要即时撤回时使用经授权的代理访问 |
| 首次／回访进度 | 空空间、草稿待确认、已有人物、已珍藏、旧资料待导入 | 新用户从一位人物开始。回访以历史与未完成动作为入口。恢复已有账号或导入资料保留原来源，单列增长资格 |
| 客户端网络与提交 | 本地草稿、提交中、结果未知、后台确认、失败可重试 | 断线时保留可编辑输入。重复提交沿用原操作标识。结果未知优先查原结果。只按权威状态展示保存、扣款和到账 |
| 媒体与生成任务 | 媒体待校验、可读、失败、撤权。任务排队、执行、成功、失败、取消 | 区分已选文件与已保存媒体。用户明确停止后阻断迟到回复。切号或关闭页面时，后台受理的订单或任务仍按原账号及授权处理 |
| 回忆与分享 | 候选、已确认私有、已授权分享、已撤回或已移除 | 用户确认原文后可检索。公开访问按单独投影与凭据。移除后失效的搜索、缓存和异步写回需要一并验收 |
| 寄礼、邀请与支付 | 寄件已受理、已抵达、已拆开。邀请待加入、待首条回忆、已获奖。支付待确认、已付款待发放、已到账、已关闭、退款中或已退款 | 三类状态各自独立。系统消息从已提交的业务事件产生。关 App、切账号或退款时都按原记录找回并更新，避免前端重复记账 |

## 还要提前验证的事项

- **首发与平台**　确定地区、发行渠道、首发功能和目标用户。现有 Android 是 USB 联调壳，发布包需验收签名、无电脑启动、安装升级、权限与回跳、弱网和进程恢复。启用账号创建时，分别核对商店要求的注销入口。按发行平台验收第三方 AI 数据共享的明确授权和应用内生成内容举报。 [Android 配置](../mobile/android/app/build.gradle) · [Apple 注销规则](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion) · [Google Play 注销规则](https://support.google.com/googleplay/android-developer/answer/13327111) · [Apple 审核指南](https://developer.apple.com/app-store/review/guidelines/) · [Google Play 生成式 AI 政策](https://support.google.com/googleplay/android-developer/answer/13985936?hl=en)
- **安全与适用性**　合成资料内测优先。首发若面向中国大陆公众提供持续拟人化互动，提前核对适用性，确定年龄门槛、素材权属与用途、生成标识、停止互动、数据复制与删除、风险处置和安全评估。把策略、人工处理职责和验收样例一起列入发布门槛。 [人工智能拟人化互动服务管理暂行办法](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)
- **迁移与兼容**　先定义正式账号和稳定 ID，再做导入。旧资料先确认归属，逐条核对人物、原文、媒体和历史引用。迁移预演、版本升级和故障回退都要验回读。用账号、来源批次与旧对象 ID 去重。Vite 预览数据与正式账本分开。 [本地账号模型](../frontend/src/model.ts) · [预览账本](../frontend/src/gifts/store.ts) · [预览入口](../frontend/src/main.tsx)
- **性能与可运营性**　首期记录发码成功率、人物建立到首次回复、珍藏到原文回读、AI 延迟和任务积压。增长阶段再看赠礼完成、邀请资格与支付到账。用脱敏的事件标识和分段计时。首条经用户确认且可读回的原文作为核心激活指标，排除演示和导入。拿试点结果决定性能、预算、恢复时间和数据丢失目标，并演练回调补单、后台权限和备份恢复。
- **已有体验与成本**　主题、语言、字号、动效、场景机位、环境音和固定功能介绍继续由客户端维护。账号内文本检索、PostgreSQL 队列和私域资料先做扎实。大型独立索引、跨端偏好和草稿同步、远程推送、更多登录渠道和实时媒体由需求和实测决定。

| 启用门槛 | 进入条件 |
| --- | --- |
| 合成资料联调 | 用测试账号和虚构人物证明写入、读取、隔离和故障恢复。保持真实公众入口关闭 |
