# 西界前端与后台交互清单

基线为当前 `xijie figma` 前端。按用户可到达的入口和实际调用链整理，供下一步划分后端职责、建模和定义接口。页面、浮层与不同入口可以复用同一份业务数据。

**阅读约定**　「本地」表示浏览器或 WebView 内完成。「演示」表示规则、计时或示例代替了真实服务。「预览接口」表示当前 Vite 中间件确实处理了网络请求。表中的后台职责是对接目标。涉及可选能力的产品决定见最后一节。

| F05 | 直达 `/relay` 或 `/relay/:id` → 发起接力、加注祝愿、查看进度、兑换回程寄件 | 独立预览路径和账本。访客 Cookie 保存发起或参与线索，服务记录席位、祝愿和兑换。兑换记录保存在接力里，主应用导航当前未接入接力入口 | 如保留公开接力，需决定是否与礼物权益互通，明确席位限制、领取身份和旧链接处理。分别定义接力与 F03 共创目标的进度和奖励来源 |
| F06 | 相见 → 新功能推荐／产品更新 → 邀请或星图搜索 | 仅开发模式下由 `?preview=discovery` 触发的本地演示，消隐状态在当前前端会话内 | 随版本发布的固定更新可保留在客户端。需要运营定向投放时，再定义内容、版本与受众、有效期、展示次数及跨端已读状态 |

## 2. 登录与支付的前端交付范围

本节记录登录和购买的目标交互，以及原型已接到的状态。当前验证码、第三方授权、报价与收银台均为本机演示。

### 登录与账号安全

| 编号 | 前端需完成的交互 | 后台或原生接入要确认的事实 |
| --- | --- | --- |
| A06 | 登录页提供手机号验证码与当前可用的其他方式。收码时也可改号码、重发或切换方式。保留仍有效的手机号和邀请来源。第三方授权取消后回到原表单 | 短信发送、冷却、码过期、错误及限流分别返回。切换方式后丢弃旧流程的回调。第三方授权应处理提供方不可用、用户取消、授权完成及 App 回前台。正式成功反馈在会话建立后显示 |
| A07 | 我 → 账号与安全 → 查看已绑定的方式、验证后绑定或换号、解除绑定。退出和切换账号有明确反馈 | 一个西界账号可关联多种已验证的登录身份。身份已被其他账号占用时显示冲突，通过验证流程解决。解绑需保留可用的登录方式。切换到另一个账号时隔离聊天、回忆、资产与草稿 |
| A08 | 首次登录进新手流程，老用户恢复原资料。从邀请链接进入时承接邀请，从受登录保护的操作返回原入口。会话过期后能重新验证 | 由后台返回账户与会话结果，以及是否首次注册。授权或重新登录后校验返回目标仍可访问。邀请归因使用真实注册结果。迟到的回调不能把界面切到错误账号 |

首发方式建议以**手机号验证码**作为基础入口。中国大陆可加入微信登录。面向海外时，可按发行渠道加入 Apple 或 Google 登录。若 iOS 用微信、Google 等第三方服务登录主账号，需核对 App Store 对等登录选项要求及适用例外。Google 登录在 Android 可由原生 Credential Manager 承接授权，WebView 负责触发和回到业务入口。 [Apple 审核指南 4.8](https://developer.apple.com/app-store/review/guidelines/) · [Google 登录接入指南](https://developers.google.com/identity/siwg/best-practices)

### 支付、订单与购买权益

入口建议放在「我 → 资产与记录」下。聊天中寄礼物时，只有当可用邮资、库存和券不足且当前有可购买商品，才给出购买入口。返回时保留收件人、选中的礼物与留言，用户可继续确认寄出。具体付费商品待定，可先选一类消耗品或一次性权益跑通。若加入订阅，再补周期、续费、取消和管理入口。

| 编号 | 前端需完成的交互 | 后台或原生接入要确认的事实 |
| --- | --- | --- |
| G01 | 展示当前可购商品。确认页写清商品、数量、实付金额与币种，展示这一单可用的支付方式 | 按发行渠道、商店地区、商户资质、设备和商品类型确定是否可卖、价格与可用方式。商店支付展示与商店结算一致的价格。交易与设备语言分别判断 |
| G02 | 确认购买 → 通过系统收银台或外部支付页继续 → 回到 App 或网页。处理拉起失败、取消、换方式和回前台 | 把购买尝试与当前账号、商品及已确认报价关联。应用与支付平台通过对应的 SDK、系统收银台或托管支付页交接。换方式前核对旧单是否已关闭或可安全取消。旧单结果未明时，继续查询同一笔订单 |
| G03 | 展示待付款、待确认、已付款待发放、权益已到账、取消、失败及退款状态。离开或重开后可查询订单 | 后台验单、核对订单金额及账号，按唯一交易号幂等发放。页面回跳只触发查询。支付渠道超时、回调重复、通知延迟或客户端退出时，仍可查回同一笔结果 |
| G04 | 「资产与记录」提供订单列表、订单详情和可用的售后入口。支持查看退款进度及对应的权益变化 | 区分真实交易流水、试用邮资和赠礼券来源。按渠道处理退款及对账，明确退款时权益已使用的处理方式。订单归属于发起购买的账号 |
| G05 | 对支持恢复的购买提供恢复入口。重装或换设备后刷新已购权益和仍可用的消耗品余额 | 按商品和发行渠道恢复可恢复的权益。消耗型邮资余额以西界账户的已入账和已消费流水为准，恢复和重放不能重复加余额。 [Apple 购买与恢复指南](https://developer.apple.com/in-app-purchase/) |

**支付渠道候选**　下表以 App 内虚拟礼物、消耗型邮资和 AI 数字权益为讨论对象。最终以首发地区、商店发行方式、商品及商户审核结果为准。

| 发行入口 | 支付候选与约束 |
| --- | --- |
| iOS App Store 版 | 数字商品按 Apple 内购基线设计。替代付款或外部购买引导按具体商店地区和资格核对。Apple Pay 的网页收款场景见下表。 [App Store 审核指南 3.1](https://developer.apple.com/app-store/review/guidelines/) · [Apple 内购设计规范](https://developer.apple.com/design/human-interface-guidelines/apple-in-app-purchase) |
| Google Play 版 | 数字商品按 Google Play Billing 基线设计。符合条件且参加对应计划的地区可评估替代结算。 [Google Play 付款政策](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en) · [Play Billing 接入指南](https://developer.android.com/google/play/billing/integrate) |
| 中国大陆 Android 其他发行渠道与独立网页 | 微信支付、支付宝为候选。先核对各 Android 渠道的规则与商户资质。按实际入口分别接原生 App、微信内网页或外部浏览器，网页支付产品及唤起方式随场景变化。 [微信支付产品](https://pay.wechatpay.cn/doc/v3/merchant/4012068590) · [微信 H5 支付](https://pay.wechatpay.cn/doc/v3/merchant/4012791845) · [支付宝开放平台](https://open.alipay.com/support/supportCenter.htm) |
| 海外独立网页 | 可从银行卡开始，Apple Pay、Google Pay 按地区、币种、支付服务商及设备能力补充。若选用托管收银台，前端接入下单、跳转与结果恢复。 [Stripe 支付方式与托管收银台文档](https://docs.stripe.com/payments/payment-methods/integration-options) |

**联调验收**　收码时换登录方式，取消授权后能回到原表单。用已绑定的不同方式登录能看到同一空间，换另一个账号后资料和资产隔离。支付取消后仍能继续编辑赠礼。支付回跳、断网和重开 App 后能查看同一订单。重复通知、重试或恢复购买时，确认只入账一次，并在退款后同步对应的权益状态。真机验收还需覆盖系统收银台、原生 SDK 回跳和进程重启。

## 3. 当前实际的 HTTP 调用

三组中间件注册于 `vite dev` 和 `vite preview`。状态写入操作系统临时目录中的 JSON 文件，浏览器用各自的预览 Cookie 识别访客。邀请及共创领券还接收客户端传入的 `owner`。这些行为可以验证预览链路，正式账户、账户级授权、权益持久化和跨进程并发需要独立设计。表中 `:id` 和 `:token` 代表路径参数。

| 方法与路径 | 用途 | 调用位置 |
| --- | --- | --- |
| `POST /api/gifts/new` | 创建共创目标，以请求 ID 重试 | 共创创建 |
| `GET /api/gifts/:id` | 读取目标、贡献进度和当前访客可用操作 | 共创详情及轮询 |
| `POST /api/gifts/:id/help` | 提交一次贡献 | 共创访客页 |
| `POST /api/gifts/reward/:token` | 将获奖资格认领至预览身份 | 共创详情或返回主应用领券 |
| `GET /api/gifts/reward/:token` | 服务端也支持校验令牌资格 | 当前业务客户端领券走 `POST` |
| `GET /api/invites/session` | 初始化访客 Cookie | 邀请客户端登录预处理 |
| `GET /api/invites/public/:id` | 校验邀请并读取展示名称 | 公开邀请页 |
| `POST /api/invites/login` | 建立预览身份并尝试绑定邀请 | 应用登录或恢复 |
| `POST /api/invites/create` | 创建或取回账号邀请 | 邀请浮层 |
| `POST /api/invites/status` | 读邀请进度及奖励标识 | 邀请浮层、奖励刷新 |
| `POST /api/invites/memory` | 登记首次记忆标记 | 本地保存完成后的事件上报 |
| `GET /api/relay/home` | 读该浏览器发起的接力及回程资格 | 公开接力首页 |
| `POST /api/relay/new` | 创建或恢复接力 | 接力创建 |
| `GET /api/relay/:id` | 读接力详情和进度 | 公开接力详情 |
| `POST /api/relay/:id/fuel` | 加入接力并记录祝愿 | 接力访客页 |
| `POST /api/relay/:id/redeem` | 使用参与资格兑换回程寄件 | 接力兑换 |

公开页面路径由前端分流。`/design-interaction` 是独立的交互预览页。Android debug 包的相对请求会通过 `adb reverse` 到电脑的 Vite 地址，正式应用需明确 HTTPS API 地址、登录态载体，以及浏览器分享链接如何回到 App。发布静态产物时，Vite 的中间件需由已部署的服务接替。

## 5. 后续设计顺序与验收路径

建议先定义**身份、人物、媒体、会话和回忆**的共用对象与授权，先串通一次真正可恢复的「找到 TA → 聊天 → 珍藏 → 从星图打开原文」。空间动态复用这些身份和媒体。AI 文本、回信与动态若接入真实生成，可共用素材和授权规则。资产流水与邀请归因可并行设计，正式接入时以登录和已确认的记忆事件为基础。

| 路径 | 可观察的结果 |
| --- | --- |
| A → B → C → D | 同一账号在两台设备看到同一人物、消息和回忆。换账号后只看到新账号有权访问的内容。刷新或离线重试不会重复创建人物或消息。历史回忆缺少来源时仍能查看原文 |
| C05／B07 | App 关闭期间到期的书信仍按设定处理，重启后回信只出现一次。若上线提醒，按用户启用的日期、时区和渠道送达 |
| D → E | 从聊天送出礼物后，资产扣减、回执、投递与会话卡片能够逐项核对。连点、断网后重试及两设备抢用同一张券时，资产结果一致 |
| F01 → D01 → F02 → E05 | 好友通过邀请首次注册并确认首条合格回忆后，双方各到账一次。重复上报、老用户和自邀等场景按约定处理 |
